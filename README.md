# Weather Forecast for Sprinter DSS

Версия 0.2.1.

Weather Forecast — клиент прогноза погоды для Sprinter DSS. Он читает
необязательный `WEATHER.CFG`, выбирает UNET backend, получает через Gopher и
строго разбирает потоковый WX1. `WEATHER.EXE` показывает текущие условия и
прогноз в графическом режиме 320×256 с погодными пиктограммами;
`WEATHERC.EXE` предоставляет самостоятельный текстовый интерфейс.

Автор: Dmitry Mikhalchenkov

FidoNet: 2:5030/1997.10

Поддерживаются CRLF, CR и LF ответы WX1, но один ответ обязан использовать
только один тип окончания строки. `WEATHER.EXE` сразу загружает прогноз,
показывает часы и автоматически обновляет прогноз каждые 5 минут. Интервал
задаётся одним аргументом в минутах: `WEATHER 10` (допустимо `1..1440`).
`WEATHER 1` повторяет запрос через 60 секунд после завершения предыдущей
попытки. Аргументы читаются через указатель `IX`, переданный DSS: поддерживаются
раскладки командной строки классического DSS и Estex-DSS. Ожидание использует
`EI/HALT`, а отсчёт — секунды RTC через `DSS_SYSTIME`.
`R`/Enter запускают обновление сразу, F1 открывает помощь, Esc завершает
программу. При ошибке обновления на экране остаётся последний успешный прогноз.
В помощи часы продолжают идти, а отсчёт до следующего запроса приостанавливается.
`WEATHERC.EXE` сохраняет прежний текстовый режим с ручным повтором по `R`/Enter.

## Зависимости

```sh
git submodule update --init --recursive
```

Для сборки нужны:

- `sjasmplus`;
- Python 3.10 или новее;
- `zip` для `make package`;
- `mtools` (`mformat`, `mcopy`, `mdir`) для `make image`.

Готовые `UNET*.DLL` берутся из манифеста закреплённого рекурсивного сабмодуля
`extern/unet_libs_asm` и никогда не пересобираются этим проектом. Текущий
комплект: `UNETESP.DLL`, `UNETRTL.DLL` и `UNET509B.DLL`.

## Сборка

```sh
make
make weatherc
make console
make test
make package
make image
make debug-image
```

Результаты:

- `build/WEATHER.EXE`;
- `build/WEATHERC.EXE`;
- `distr/weather-forecast.zip`;
- `distr/weather-forecast.img`;
- `distr/weather-debug.img` — диагностический образ с test `WEATHER.CFG`.

Перед запуском на Sprinter сеть должна быть поднята:

- ESP/Wi-Fi: `NETUP`, публикующий `NET=WIFI`;
- RTL8019A: `NETCFG -i`, затем `IFUP`, публикующие `NET=RTL`;
- 3Com 3C509B: `NETCFG -i`, затем `IFUP` из кита 3C509B, публикующие
  `NET=509B`.

Стандартный `UNETLD` принимает без учёта регистра тег из 3–4 символов
`[A-Z0-9]` и загружает `UNET<TAG>.DLL`; исключение `NET=WIFI` преобразуется в
`UNETESP.DLL`. Поэтому новый совместимый TCP backend можно добавить рядом с
EXE без пересборки программы. Перед запуском всегда выполните утилиту настройки
выбранного backend. Актуальный libman умеет использовать текущий каталог как
fallback.

`WEATHER.CFG` необязателен. Без него используется
`go.sprinter.ru:70/weather/zx`. Дистрибутив содержит безопасный шаблон
`WEATHER.SMP`: после осознанного редактирования пользователь сам переименовывает
его в `WEATHER.CFG`, поэтому сборка не перезаписывает существующую настройку.
Исходник шаблона находится в `resources/WEATHER.CFG.sample`.

`WEATHER.EXE` — графическая версия 320×256 с часами в формате `HH:MM:SS`.
Сетевые стадии и ошибки после первого прогноза занимают нижнюю строку;
последний успешный прогноз остаётся на экране во время обновления и при ошибке.
Её primary loader загружает
resident runtime в отдельную страницу WIN2 и до его запуска распаковывает
встроенные Hrust-ассеты в пять DSS-страниц. Сам runtime не содержит depacker-а
и после старта не зависит от диска. Для неё рядом с EXE нужны `AFNT320.DLL` и
`GFX320.DLL`.
`WEATHERC.EXE` остаётся самостоятельной текстовой версией. Обе программы
используют общий необязательный `WEATHER.CFG`.

Редактируемые исходники пиктограмм находятся в `resources/gfx/`: отдельно
`64×64` для текущей погоды и `32×32` для прогноза. Требования к PNG и палитре
описаны в `resources/gfx/README.md`.
